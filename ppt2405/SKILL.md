# ppt2405

目标是做出完整、专业的文献汇报，而不是填满所有示例页。模板一与模板三共同定义蓝白学术样式，模板二补充证据对比与 AI 概念示意。使用本 skill 随附的模板，不另选主题。

## 入口与资源

将本文件所在目录作为 `SKILL_DIR`，所有相对资源均从这里解析。输出写到当前任务的新项目目录，保留输入和内置模板。

- `assets/ppt2405.pptx`：26 类可编辑样例页，复制整页保留母版、表格和图片。
- `assets/ppt2405.potx`：手动使用的原生模板。
- `assets/ppt2405-preview.pdf`：WPS 原生导出的26页样式参考；公式以 PPTX 中可编辑对象为准。
- [版式与适配规则](references/style-and-layouts.md)：开始规划时读。
- [研究和素材管理](references/research-and-assets.md)：论文/大纲信息提取及外部补充时读。
- [图表提取](references/figure-extraction.md)：需要从 PDF 截图时读。
- [组合接口](references/composition-api.md)：生成或修改页面前读；准确槽位见 `references/layout-catalog.json`。
- [交付检查](references/quality-and-delivery.md)：制作和复核时读。

在 Codex 桌面环境中，若提供 `load_workspace_dependencies`，先用它获取 Python/Poppler 运行时；若未提供，则检查 PATH 和已有运行时目录，并实际验证 Python 可导入所需依赖。不要假设系统 `python` 可用。脚本用 Python 3.10+，依赖见 `requirements.txt`，图表渲染另需 Poppler；使用已验证的 Python 绝对路径运行。缺少渲染器时使用本地 WPS/PowerPoint。若当前环境有演示文稿、PDF、图像生成工具，按需配合使用。

## 制作流程

1. **读输入并建立项目。** 论文输入：阅读全文、图注、实验设置和限制；有补充材料则按需读。大纲输入：保留用户逻辑，逐项找证据。明确听众、时长/页数和范围；未指定时按内容提出合理假设并继续。可以用 `scripts/init_project.py` 建立分类目录和源文件副本。没有必要因作者单位、日期等可省略字段中断。
2. **补齐事实。** 论文是其方法和结果的第一来源。围绕确实缺失的背景、对比、数据做检索，优先原论文、官方项目和数据发布方。每个数字记录单位、数据集、指标方向、条件和原始位置；不把不同条件的结果直接并列为性能结论。大纲中的主张也须核验，没找到证据就改写、标明尚待验证或省略。
3. **先做逐页计划。** 在 `analysis/storyboard.json` 中记录每页目的、核心信息、证据/布局/素材 ID、预计密度、配图需求与作用、文字对齐判断、`semantic_emphasis_plan` 和讲解要点；字段示例见 [研究和素材管理](references/research-and-assets.md)。有核心论断的正文页通常选 1–3 组有证据依据的结论、转折或对比数值，以深红 `C00000` 加粗呈现。把原理、方法迁移、实现机制和实验证据逐层展开；关键优势对应可见证据，方法关系用架构/时间轴表达，真实任务用设置与结果配对。页数与内容匹配，目录可省略、改名、重组。若有参考成稿，按同主题页比较视觉层级和讲解节奏，不机械匹配页数。
4. **准备素材。** 背景、动机和应用场景页主动寻找能解释内容的相关真实图片，来源可为其他论文、官方项目或可信网络页面，不局限于输入论文。查看原始页面和实际图片后选用；没有合适真实图时可调用图像生成工具补充概念/场景/机制示意，并保留“AI生成示意图，非论文原图”。配图服务于解释，不强行每页加图。将论文图表、数据表、外部真实图/视频、AI 示意图分类登记。论文图按完整图域渲染并逐张对照原页；长图注与来源留在记录/备注，展示图片保留全部科学信息，详见 [图表提取](references/figure-extraction.md)。作者提供的真实演示可使用视频或关键帧。
5. **按模板组版和适配。** 选最适合内容的样例页，可复制、重复、删除和重新排序。优先 `scripts/compose_deck.py` 保留精确格式。普通说明中的变量也用原生 OMML 数学，表格可编辑，图片等比 contain。短标签/卡片文字通常水平、垂直居中；长正文按框宽、语言与行数选择两端或左对齐，避免拉大字距。主标题沿用模板，正文内边距、留白和视觉重心逐页调整，详见 [版式与适配规则](references/style-and-layouts.md)。完整图片仍难读时改变图文比例、换版式或拆页，不能仅凭 fit 通过。视频可在组版后用 `scripts/embed_media.py` 替换已排好的海报图，见 [组合接口](references/composition-api.md)。
6. **检查并交付。** 使用严格生成模式，清除未填提示、原样例数据、示例图和无关页。核对来源与每页实物，逐页渲染检查，并用 WPS/PowerPoint 检查公式、表格及最终呈现。处理工具报告后仍需视觉判断。交付可编辑 PPTX、预览 PDF 和项目素材/来源清单；用户只要 PPT 时减少附带输出。中间检查自主完成，只有用户指定的验收节点才暂停。

## 关键约束

- 不凭空补数据、引文、作者、实验结论；AI 图片不能表示实测结果。
- 幻灯片不添加“来源：作者 · 图号 · PDF页码”等小字，完整来源放对应页备注与素材清单。来源槽自动隐藏；不要用白字、页外文字替代。保留图轴/图例、必要实验条件、AI 示意标识及封面书目信息。
- 数学符号、上下标、分式、向量使用原生数学结构；不要以斜体普通文字或截图代替。中文释义使用微软雅黑，公式使用 Cambria Math。
- 完整图域至少保留子图编号、坐标轴、图例、颜色刻度和关键注释。局部放大必须另附完整总览，明确“局部”，保留来源坐标。
- 字体测量与结构检测只是预检。未经逐页看图，不能声称排版或提图已验证。
- 当前 helper 不能自动理解任意论文或任意 LaTeX。由代理阅读和规划，脚本负责可重复的提取/排版动作；复杂公式或布局需要按接口扩展并重新渲染，不得悄悄转为不可编辑整页图。
