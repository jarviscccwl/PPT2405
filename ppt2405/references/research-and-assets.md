# 研究与素材管理

## 输入处理

论文路线先记录题目、作者、发表渠道、版本、年份/DOI，提取任务、问题、方法、假设、数据集、基线、结果和局限。按页定位公式、图、表及图注。PDF 页码与论文印刷页码同时记录；二者可能不同。

大纲路线保留用户主题与叙事顺序，列出“已提供事实 / 需要研究 / 不能验证”的内容。可以补充更适合解释的证据，但不要擅自改成另一篇论文的汇报。未指定时默认中文学术汇报，页数按信息量确定；重要假设在进度说明中简述即可。

外部检索优先原论文或正式版本、作者项目页、数据集/机构/标准的官方发布。发现论文版本差异时明确本次采用版本。搜索结果摘要只用于发现来源，最终事实须读到原始正文或表格。记录实际访问日期。无法获取原文时不要编造页码或数据。

## 项目目录

`scripts/init_project.py <新项目目录> --source <论文或大纲文件>` 复制输入并建立：

```text
sources/                  原始输入及补充来源，保留原件
analysis/                 阅读笔记、逐页计划、证据清单
assets/paper-figures/      论文完整图域
assets/paper-tables/       原表截图及逐格核对后的数据
assets/data/               CSV/JSON、单位、转换/计算依据
assets/external-images/    真实外部图片及页面来源
assets/external-media/     官方演示视频、完整帧、时间戳与来源
assets/ai-concepts/        AI示意图、提示词和生成记录
assets/brand/              已确认的徽标/校园/机构资产
build/                    组版JSON、中间PPTX、渲染页、检查记录
output/                   最终PPTX与预览PDF
```

`sources/manifest.json` 登记输入副本、SHA256、原路径。后续网络来源追加 `id,title,url,accessed_at,version,local_path,sha256`，有版权/许可信息时如实记录，不推断授权。

`analysis/storyboard.json` 每页先明确内容依据、配图任务和文字布局，再决定红粗样式，例如：

```json
{
  "slide": 3,
  "core_message": "本页已核验的核心结论",
  "evidence_ids": ["E001"],
  "visual_need": "展示该技术实际面对的应用环境",
  "visual_role": "background-context",
  "asset_ids": ["A001"],
  "alignment_plan": [{"slot": "background", "align": "justify", "vertical_align": "top", "reason": "较宽框内的多行中文正文"}],
  "semantic_emphasis_plan": [{
    "target": {"kind": "text", "slot": "takeaway"},
    "phrase": "已核验的关键差异",
    "role": "对比数值或结论短语",
    "evidence_ids": ["E001"],
    "color": "C00000",
    "bold": true
  }]
}
```

`visual_need` 说明观众需要看懂什么，`visual_role` 区分背景情境、机制说明、实验设置或结果证据；无需配图时写明原因。`asset_ids` 指向实际选用素材。`alignment_plan` 记录会改变的文本槽与原因，示例槽名应换成所选布局真实存在的名称。`phrase` 必须匹配将上屏的完整短语或数值，`role` 说明它是核心结论、机制转折还是同条件比较，`evidence_ids` 指向支撑事实。表格目标可写 `{"kind":"table","slot":"results-table","row":1,"column":2}`，行列从 0 起算并包括表头。有核心论断的正文页通常选 1–3 组；没有正文重点的封面/目录用空数组。这些字段属于分析计划，不直接传给 `compose_deck.py`；组版时将强调转为 run/单格的 `color`/`bold`，将对齐转为 text 的 `align`/`vertical_align`，验收时对照 Office 画面。

`analysis/evidence.json` 的每条事实至少包含：

```json
{
  "id": "E001",
  "claim": "已核验的具体主张",
  "source_id": "S001",
  "locator": {"pdf_page": 5, "section": "4.2", "figure": "Fig. 3"},
  "value": null,
  "unit": null,
  "conditions": "数据集、划分、指标定义、测试设置",
  "status": "verified",
  "used_on_slides": [3]
}
```

`assets/manifest.json` 统一索引所有入选素材：`id,kind,path,source_id,locator,purpose,used_on_slides,review_status`。`kind` 区分 `paper_figure,paper_table,real_data,external_image,external_video,video_frame,ai_concept,brand`。其他论文的图存为 `external_image` 并记录该论文的 DOI/URL、版本和图号；不混入当前论文的 `paper_figure`。提图 helper 的独立 manifest 通过路径关联，保留其详细边界和审核记录。

先保存完整证据。数字抄录逐项核对行列、单位、误差含义和箭头方向；计算值保留输入、公式和精度，不伪装成论文原值。曲线没有数据时使用完整原图；确实需要数字化时明确标识估计并记录误差，不据像素生成“精确原始数据”。

正文、表格、附录或不同版本不一致时，记录冲突位置与采用口径，不混合成一个数字。作者报告的总体提升与自行复算分开；公开表经四舍五入时，不能仅凭复算末位差异断言原结论错误。重要结果同时写比较对象、统计范围和指标方向。

## 背景与场景配图

为背景、动机和应用场景页主动检索与本页论点直接相关的真实图：先看相关论文/综述、作者与机构官方项目，再考虑有明确出处的可信网页。检索词应包含技术对象、应用环境和本页要解释的关系；不能只搜索宽泛主题后选一张装饰图。当前论文已有合适图时可以采用，但仍按页面解释需求判断，不把输入论文当唯一素材库。

打开实际来源页和原图，核对图片展示的对象、时间/环境、清晰度和是否有误导性标注。搜索缩略图、摘要和下载文件名都不能代替核验。相关实验图片只能说明其原研究情境，不作为当前论文的结果。记录来源页 URL、原图地址（可获得时）、访问日期、作者/机构、许可信息及选用理由。其他论文图沿用完整图域提取和逐图检查方法。

把候选与页面图框一起评估：选能清楚展示关键对象、分辨率足够且比例合适的图；保留必要科学信息，避免无关拼贴。没有合适真实图时，记录检索范围及不采用原因，再按下节生成解释性示意；也可用可编辑简图。无解释价值的配图不必插入，不用装饰图片填空。

## 真实视频与帧序列

优先作者官方项目页中实际存在的媒体地址，不猜URL。记录来源页、媒体URL、访问时间、原始文件SHA256、分辨率/时长；选帧记录时间戳。出处、链接和协议留在对应页备注与素材清单，不添加上屏来源小字。视频中的成功个例不能冒充总体成功率。采用本地MP4嵌入时，用完整帧作海报，保持宽高比；静态PDF只显示海报，必要时另外保留带时间戳的关键帧。图像生成不能补画真实实验中未出现的过程。

## AI 示意图

需要解释概念、环境或流程，而检索到的真实图片无法清楚支持页面内容时，可使用 AI 示意图；用户已明确要求生成时也可直接采用。图表和实验结果仍来自真实材料。调用当前可用的图像生成工具；有 `imagegen` skill 时按其要求执行。图片生成失败时可以改用合适的真实图或可编辑简图，不伪称生成成功。

提示词先明确用途、科学概念和限制，再指定蓝白背景、`#0B4FA1/#0056A5` 主色、目标长宽比、留白和图上必须出现的实体。尽量让关键术语/变量由 PPT 原生文本或公式添加，避免生成图中的伪文字。不要生成看似真实的测量刻度、统计数字或实验照片来证明结果。

保存提示词、模型/工具（可获得时）、生成时间、文件 SHA256、采用理由和科学审查记录。页面保留 **AI生成示意图，非论文原图**。重用模板25时也需要替换其点云示例，除非当前主题确实适用且明确记录来源。

内置点云示例的生成来源见 `ai-sample-provenance.json`，仅供模板演示。

## 来源放置

幻灯片不显示“来源：作者 · Fig. 3 · PDF第4页”等来源小字，也不将其改成白字、极小字或移到页外。对应页备注保存可访问 URL/DOI、论文页码、图表编号、数据条件和素材 ID；项目中保留完整来源与素材清单。组版 helper 自动隐藏来源槽，并将兼容旧计划的来源文字及图片/表格 `source` 写入备注，详细字段见组合接口。

外部背景与论文自身结论明确区分。页面仍保留观众理解内容所需的实验条件、图轴/图例、子图编号、局部放大标记和 AI 生成示意声明；封面的论文题目、作者与发表信息也保留。这些信息不属于要移除的来源页脚。引用图片中的原生署名、水印或许可标记不得为了清理页脚而裁掉；若影响版式，选择合适的其他素材。

借鉴项目：[ppt-master](https://github.com/hugohe3/ppt-master)。本 skill 借鉴其源材料、规划、素材准备、编辑和复核的分层，使用本项目自己的模板与脚本，不依赖 ppt-master 安装。
